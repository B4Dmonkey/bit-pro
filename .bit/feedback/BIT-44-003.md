Happened while BIT-44.4 was in progress, under track BIT-44 ("bit:analyze and bit:ruler"). No bar covers it; it was fixed in its own commit.

Scope (BIT-44) says, in its Decisions: "**Topic names have no required format.** bp makes any name safe as a file name, the way feedback note paths are built, instead of refusing it."

Bar BIT-44.1 says: "`researchPath` is `pathologize.Join(s.researchDir(track), pathologize.Clean(topic)+".md")` so the topic is always exactly one segment". Its test `TestServeMCPCmd_ResearchWriteKeepsAnUnsafeTopicInTheTrackFolder` writes topic `"../../tasks/" + testTrackID` and expects a file inside the track's research folder.

What happened:
- Up to commit 52c9fc5, bad topics were cleaned, not refused. `../../tasks/FOO-1` was cleaned to `tasksFOO-1.md` (earlier `....tasksFOO-1.md`), and only an empty or dots-only topic was refused. Feedback note BIT-44-002 records that step: the user decided to strip leading dots.
- I then reported that `". ."` (dots and spaces) still got through as `file.md`, because `pathologize.Clean` never returns an empty string.
- The coordinator relayed the user's direction: "we should avoid relative paths if possible". It then relayed the decision: "research topics that look like paths should be rejected with an error, not cleaned". Specifically: "For both research_write and research_read, reject a topic that contains `..`, `/` or `\`, or that is only dots and spaces (`...`, `. .`, ""). The error must name the problem, and a rejected write must create no file. Keep `.hidden` → `hidden.md`." And: "validate the raw topic before pathologize runs. pathologize still cleans whatever passes."
- This reverses the scope Decision's approach ("makes any name safe ... instead of refusing it") for path-like topics. The scope body was not changed.
- For `research_read`, an empty topic was not rejected. Since BIT-44.4, an omitted or empty topic means "list the track's topics", so only `research_write` rejects `""`.

The work required: `validateTopic` in `task/research.go` refuses, before `pathologize` runs, a topic that is empty or only dots and spaces ("is empty"), contains `..` (`contains ".."`), or contains `/` or `\` ("contains a path separator"). Both `WriteResearch` and `ReadResearch` call it. The 44.1 escape test and the traversal case of the leading-dot test were replaced by `ResearchWriteRefusesAPathLikeTopic` and `ResearchReadRefusesAPathLikeTopic`, which expect errors.
