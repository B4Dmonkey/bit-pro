Verse 1 (BIT_DIR env var / --bit-dir flag) does not work ergonomically. The mechanism exists but nothing sets it — bit:do runs bp commands in a worktree without exporting BIT_DIR, so all task state writes land in the worktree's .bit/ copy instead of the canonical one on main. The TUI on main shows stale state; the user has no ergonomic path to routing correctly today.

Deeper unknowns to resolve before re-implementing:

1. Whether .bit/ is git-tracked varies by project. In this project it is tracked, so worktrees each get their own .bit/ copy. In projects where .bit/ is untracked (gitignored), it would not appear in the worktree at all — bp would fail entirely. The right solution likely differs per case.

2. A config-file approach (e.g. a canonical_bit_dir key in .bit/config.toml or a separate .bitconfig) may be more ergonomic than an env var — it's set once per repo and picked up automatically, rather than requiring every caller to export a variable.

3. This may need its own track rather than a one-bar fix inside BIT-23. Revisit after the approvals verses (3–6) are complete.
