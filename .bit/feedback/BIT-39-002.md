Happened during bit_plan on BIT-39 ("Dispatch — the daemon works queued bars
unattended"), at the gate — before any bar was written. No bar exists yet.

Two things surfaced in the same pass. They look like separate mistakes but they
share a cause, so they are recorded together.

## 1. A scope Decision asserted a code fact without checking it

The scope carries this Decision:

> - **The `claude` binary calls go in `claude/`, not `daemon/`.** `claude/sync.go`
>   already shells out to `claude` behind a `Runner` seam; spawn and `agents --json`
>   join it. This keeps `daemon` free of external-tool plumbing and avoids a second,
>   differently-shaped `Runner`.

The placement call is sound. The rationale is not. `claude.Runner` is:

```go
type Runner func(ctx context.Context, name string, args ...string) error
```

It returns only an error and discards stdout. Every current caller is a plugin
command (`plugin marketplace update`, `plugin update`, `plugin install`) where
pass/fail is the whole answer. But `claude agents --json` — the surface the scope's
own Visual aid and four of its Decisions depend on — exists only to be read. There
is nowhere for the JSON to go.

So "spike and `agents --json` join it" cannot happen as written, and the clause
"avoids a second, differently-shaped `Runner`" describes the opposite of what the
work requires: `claude/` gains a second, differently-shaped runner, or every
existing caller absorbs two return values it will discard.

The Decision was reached by reading that a `Runner` seam existed in `claude/`, and
not by reading its signature. `daemon.Runner` — `(out string, code int, err error)`
— was already sitting in the same repo as the shape that would have been needed,
which is what makes the miss visible in hindsight.

## The shared shape

Both are the same move at two altitudes: **a claim about the codebase made from the
shape of the codebase rather than from reading it.** bit_scope wrote "a `Runner`
seam exists, reuse it" without opening the signature. bit_plan wrote "this is a
loosely-drawn boundary, ask the user" without checking whether the repo already
answered it. In both cases the missing step was the same size — one grep, one file
read — and in both cases the artifact produced (a Decision, a question) was
confident enough that nothing downstream would have re-examined it.

The cost differs by altitude. The scope's version puts a false rationale into the
record that later verses build on. The plan's version spends the user's attention on
something the repo already decided, which is the specific thing the gate exists to
avoid doing carelessly — the gate protects against planning past an open question,
not against looking.
