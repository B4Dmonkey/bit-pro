What was discovered: the platform is macOS (BSD sed), and `update/normalize.sh` already
committed to that dialect in the two prior bars — `normalize_id_fields` uses `sed -i ''`
with the BSD empty-suffix argument. BSD sed has no `\U` case-conversion escape, so the
prescribed `sed` range addressing cannot perform the uppercasing the step asks for; the
only sed route is `y/abc…/ABC…/` transliterating the whole pattern space, with both
alphabets spelled out. Separately, `/^---$/,/^---$/` is a restartable range: after the
closing frontmatter delimiter it re-arms, so a later `---` line in a task body opens a
second range and the rewrite is no longer frontmatter-only — the exact boundary the
step's preamble identifies as the reason this is its own bar.

The work required `awk` instead, with an `in_frontmatter` flag whose opening delimiter
is anchored to `NR == 1`:

```
awk '
    NR == 1 && $0 == "---" { in_frontmatter = 1; print; next }
    in_frontmatter && $0 == "---" { in_frontmatter = 0; print; next }
    in_frontmatter && /^ *- / { print toupper($0); next }
    { print }
' "$path" >"$tmp"
```

Both "Claude verifies" checks passed with this (`bash update/normalize_test.sh` exits 0,
`shellcheck` clean), and the step's boundary test — a body bullet `    - bit-1.9 was
dropped` one line past the closing `---` — passes.
