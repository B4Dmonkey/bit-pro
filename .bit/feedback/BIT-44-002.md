Happened after BIT-44.1 and BIT-44.2 were committed, under track BIT-44 ("bit:analyze and bit:ruler"). No bar covers it; it was fixed in its own commit ahead of BIT-44.3.

Scope (BIT-44) says, in its Decisions: "**Topic names have no required format.** bp makes any name safe as a file name, the way feedback note paths are built, instead of refusing it."

Bar BIT-44.1 says: "`researchPath` is `pathologize.Join(s.researchDir(track), pathologize.Clean(topic)+".md")` so the topic is always exactly one segment", and its traversal test asserts: "`filepath.Rel(<dir>/.bit/research/<track>, path)` has no `..` prefix and no separator". Neither the scope nor the bar says anything about leading dots in a topic.

What happened:
- `pathologize.Clean("../../tasks/FOO-1")` returns `....tasksFOO-1`, so the file was written as `....tasksFOO-1.md`. That is inside the track folder, but it starts with `..`, so the bar's traversal test failed as written. During BIT-44.1 I loosened the check to `rel == ".." || strings.ContainsRune(rel, filepath.Separator)`, and I reported that a topic starting with `.` becomes a hidden file, asking whether leading dots should be stripped.
- The user decided that leading dots should be stripped, and that a topic made only of dots (for example `...`) should be refused as empty. This came through the coordinator: "strip leading dots from research topics"; "Topic `.hidden` must be written as `.bit/research/<TRACK>/hidden.md`. Topic `../../tasks/FOO-1` must become `tasksFOO-1.md`"; "A topic made only of dots, like `...`, should be rejected as empty."
- Found while implementing it: `pathologize.Clean` never returns an empty string. `Clean("...")`, `Clean("")` and `Clean(". .")` all return `file`. So stripping dots after `Clean` can't notice a dots-only topic. The empty check was added on the raw topic (`strings.TrimLeft(topic, ".") == ""`), and the stripping happens after `Clean`.

The work required: `researchPath` strips leading dots from the cleaned topic, `WriteResearch` refuses a topic that is empty or only dots, and the BIT-44.1 traversal test is back to the bar's original `..` prefix check.
