## What happened

At BIT-49.25 the plan's Scope said `migrate.Result` gains `Holder string` (the folder holding `.bit/`) and the cleanup messages print `<holder>`. The bar's own RED test asserts the untracked message contains `rm -rf <canonical dir>/.bit`. On macOS `t.TempDir()` is `/var/...` while the canonical path is `/private/var/...`, so a raw holder fails the test, and a canonical holder is exactly the existing `Result.Path`.

## What was done

Followed the test: no `Holder` field; the messages use `res.Path`. `Result` gained only `Tracked`, computed with `git.Tracks` run in the raw holder (`filepath.Dir(src)`), which is the main checkout. The existing worktree TestRun case asserted every git call ran in the worktree; it now checks only the HEAD calls, since `ls-files` deliberately runs in the holder.
