## 3. Hidden unknowns, checked
- **Store layout:** `<root>/tasks/<ID>.md`, `completed/<ID>.md`, `archive/tasks/<ID>.md`, `research/<TRACK>/<topic>.md`, `feedback/<TRACK>-NNN.md` (`task/store.go:16-20,33-55`, `task/research.go:16-21`, `task/feedback.go:15-21`). Dirs are created lazily by `MkdirAll` on write (`Save`, :179), so `bp add` need not create `<CODE>/`.
- **ID minting:** tracks use `NextID(prefix)`, globbing `PREFIX-*.md` across the 3 dirs (:625-635). Bars use `NextChildID` (:608-623), which needs only the parent. Feedback seq `nextNoteSeq` (`feedback.go:23-33`) globs feedback/. Only track minting needs the code.
- **sqlc:** `db/orm/` is gitignored (`.gitignore`) and generated by `just db-gen-queries`, which `just run/test/lint` depend on. A plain `go build`/`go test` on a fresh clone fails until `sqlc generate` runs, and any bar that changes queries must regenerate. sqlc and dbmate are installed under /opt/homebrew. dbmate runs through a custom modernc driver (`db/driver.go`). `db.Open` migrates on every open (`db/open.go:33`), so a per-MCP-call open re-checks migrations each time (cheap).
- **XDG in tests:** there is no global env setup in TestMain. Each db-touching test sets `HOME` to a temp dir and `XDG_DATA_HOME=""`. Today `initProject` tests never open the db; after Verse 1 all 78 do, so the fixture must sandbox HOME or a developer's own `XDG_DATA_HOME` leaks in.
- **Symlinks and case (probed on this Mac, Go 1.27):** `t.TempDir()` = `/var/folders/...`, and `filepath.EvalSymlinks` gives `/private/var/...`. `os.Getwd()` returns `$PWD` unresolved (`/var/...`) **and keeps the case the user typed**. `EvalSymlinks` also keeps the given case. `bp add` today stores `filepath.Abs` (`cmd/add.go:27`) with no symlink resolution, and SQLite `UNIQUE` is case-sensitive. So both the stored path and cwd must go through `EvalSymlinks`, and matching must tolerate case, or `cd ~/developer/...` silently fails to resolve on case-insensitive APFS.
- **`CLAUDE_PROJECT_DIR`:** read only at `cmd/serve_mcp.go:231`. Whether Claude sets it to the worktree or the main checkout in a worktree session is unverified, but longest-prefix handles both.
- **Code derivation in `bp add`:** a stdin prompt, defaulting from `.bit/config.toml` (`cmd/add.go:50-58`). In v2 an unregistered `.bit/` folder is refused, so the default source disappears and it's a plain prompt.
- **Nested registration:** `acme/` (not a repo) may contain registered repos, so `bp add` must allow a path inside another registered path; longest-prefix then picks the inner one. The track doesn't say so.

## 4. Record format: what bit:plan would have to guess
The track settles: pair files, `content` = relative path, `project`, `created_at`, `updated_at`, `branch`+`commit` (tracks/bars), `commits:[{sha,branch,at}]` (research, feedback). BIT-45 `json-schema` suggests but doesn't decide the rest. Open, with suggested defaults:
- **File naming:** `<ID>.json` + `<ID>.md`, `<topic>.json` + `<topic>.md`, `<TRACK>-NNN.json` + `.md`, side by side in today's dirs. `content` = the sibling basename.
- **Task field names:** keep the yaml tags verbatim (`id,title,status,approved,phase,phase_label,order`, `task/task.go:19-28`); they match the MCP output names. Don't store `parent` (derived, as today).
- **Empty vs omitted:** write every field (no omitempty); git fields as `""` and `[]`, never null.
- **Timestamps:** RFC 3339 UTC strings. `updated_at` bumps on every write, including a body-only `task_update` and a research overwrite.
- **Research/feedback metadata:** research `{project, track, topic, ...}`, where `topic` is the sanitized file stem; feedback `{project, id: "TRACK-NNN", track, seq, ...}`.
- **Globs:** ID, seq and topic listing switch to `*.json` (`store.go:443,467,614,626`, `feedback.go:24`, `research.go:95`) so an orphan `.md` reserves nothing.
- **Write order:** `.md` then `.json` (plain `os.WriteFile` as today; temp+rename only if wanted).
- **Formatting:** 2-space indented JSON with a trailing newline.
- **Returned path** from `research_write`/`feedback_add`: the `.md` path (what a reader opens).

## Suggested defaults for other gaps

- `pluginState` root: the resolved project path, else cwd.
